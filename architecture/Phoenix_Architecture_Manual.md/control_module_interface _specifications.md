# CTRL-001 — Main Control

## 1. Module Name

**Main Control Unit**

Module: `phx_control_main`  
RTL File: `rtl/Control/phx_control_control_unit.v`  
Testbench: `tb/Control/phx_control_control_main_tb.sv`

## 2. Purpose

The Main Control Unit is responsible for decoding the instruction opcode and
generating the primary control signals required by the PhoenixRV datapath.

It determines how the instruction should use the processor datapath, including:

- Register write enable.
- ALU operand-A source selection.
- ALU operand-B source selection.
- Data memory read and write control.
- Writeback source selection.
- Branch control.
- Jump control.
- JALR control.

The Main Control Unit performs instruction-class decoding based primarily on
the 7-bit RISC-V opcode.

The detailed ALU operation is handled separately by CTRL-002 — ALU Decoder.

## 3. Module Interface Specification

### Port Interface Specification

| Port | Direction | Width | Description |
|---|---|---:|---|
| `instruction` | Input | 32 | Complete 32-bit RISC-V instruction |
| `RegWrite` | Output | 1 | Enables writing to the Register File |
| `ALUSrcA` | Output | 1 | Selects the first ALU operand source |
| `ALUSrc` | Output | 1 | Selects the second ALU operand source |
| `MemRead` | Output | 1 | Enables data-memory read operation |
| `MemWrite` | Output | 1 | Enables data-memory write operation |
| `WBSelect` | Output | 2 | Selects the writeback data source |
| `Branch` | Output | 1 | Identifies a conditional branch instruction |
| `Jump` | Output | 1 | Identifies a jump instruction |
| `JumpReg` | Output | 1 | Identifies a register-based jump (JALR) |

### WBSelect Encoding

| `WBSelect` | Writeback Source |
|---|---|
| `00` | ALU Result |
| `01` | Data Memory |
| `10` | PC + 4 |
| `11` | Immediate |

## 4. RTL Behavior

The Main Control Unit is a combinational control circuit.

The instruction opcode is extracted from:

```text
instruction[6:0]
```
## 5. Verification

The Main Control Unit was verified using a dedicated SystemVerilog testbench:

`tb/Control/phx_control_control_main_tb.sv`

The verification testbench uses an independent reference model to generate the
expected control signals for each instruction class. The expected outputs are
then compared against the outputs of the Device Under Test (DUT).

### 5.1 Verification Strategy

Directed verification was performed for all supported instruction classes.

The following instruction types were tested:

- R-type
- I-type ALU
- LW
- SW
- Branch
- LUI
- AUIPC
- JAL
- JALR
- Invalid/unsupported opcode

For each instruction, the complete control-signal vector generated by the DUT
was compared against the expected control vector from the independent
reference model.

# CTRL-002 — ALU Decoder

## 1. Module Name

**ALU Decoder**

Module: `phx_control_alu_decoder`  
RTL File: `rtl/Control/phx_control_alu_decoder.v`  
Testbench: `tb/Control/phx_control_alu_decoder_tb.sv`

## 2. Purpose

The ALU Decoder determines the specific ALU operation required by the current
RISC-V instruction.

It decodes the instruction `opcode`, `funct3`, and, where required, `funct7`
fields and generates the 4-bit `alu_control` signal supplied to the ALU.

The ALU Decoder works together with the Main Control Unit:

- CTRL-001 determines the general datapath behavior.
- CTRL-002 determines the specific ALU operation.

The decoder supports the ALU operations required by the supported PhoenixRV
RV32I instruction set.

## 3. Module Interface Specification

### Port Interface Specification

| Port | Direction | Width | Description |
|---|---|---:|---|
| `instruction` | Input | 32 | Complete 32-bit RISC-V instruction |
| `alu_control` | Output | 4 | ALU operation control signal |

## 4. RTL Behavior

The ALU Decoder is a combinational logic module.

The following instruction fields are extracted from the instruction:

```text
opcode = instruction[6:0]
funct3 = instruction[14:12]
funct7 = instruction[31:25]
```
## 5. Verification

The ALU Decoder was verified using a dedicated SystemVerilog testbench:

`tb/Control/phx_control_alu_decoder_tb.sv`

The testbench uses an independent reference model to calculate the expected
ALU control value from the instruction fields and compares it with the
output generated by the Device Under Test (DUT).

### 5.1 Verification Strategy

The verification was performed using directed and randomized test cases.

The following instruction classes were verified:

- R-type ALU instructions.
- I-type ALU instructions.
- Shift-immediate instructions.
- Load Word (LW).
- Store Word (SW).
- All six conditional branch instructions.
- LUI.
- AUIPC.
- JAL.
- JALR.
- Invalid and unsupported instruction encodings.

### 5.2 R-Type Verification

All ten supported R-type ALU operations were verified:

```text
ADD   SUB   AND   OR   XOR
SLL   SRL   SRA   SLT  SLTU
```
